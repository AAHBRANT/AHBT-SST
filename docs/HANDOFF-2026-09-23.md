## Atualizacao integrada nesta sessao: Certificados retroativos + trava de NR-06

- PR: https://github.com/AAHBRANT/AHBT-SST/pull/90 (mergeado, merge commit)
- Commit: `7f52354 feat(treinamentos): sub-aba Certificados para lançamento retroativo`
- Pedido original do usuario: lancar retroativamente treinamentos de trabalhadores que ja estavam na obra quando o sistema entrou, com upload do certificado (PDF ou foto).

### O que foi implementado

**Sub-aba Certificados** em Treinamentos (Turmas · Certificados · Catalogo · Matriz):
- Lista central de todos os certificados, com filtro por obra/curso/situacao/busca.
- Formulario "Lancar certificado": funcionario, curso (autopreenche validade/carga horaria), origem, datas, numero do certificado (opcional), instituicao, local, e anexo do arquivo.
- Upload aceita PDF/JPEG/PNG ate 10 MB, com validacao de assinatura real do arquivo (nao confia no Content-Type declarado).
- Visualizacao inline do PDF/imagem anexado e download.

**Campo `Treinamento.OrigemCertificado`** (enum `Aahbrant`/`Externo`, default `Aahbrant` para preservar registros existentes):
- Externo bloqueia a emissao do certificado no modelo proprio da AAHBRANT (`ExportarCertificadoTreinamentoQuery` lanca `InvalidOperationException` -> 400) — a empresa nao pode atestar treinamento que nao ministrou. Ha teste dedicado (`ExportarCertificadoTreinamentoOrigemTests`) travando isso.
- O download nesse caso entrega o arquivo original anexado.

**Tabela `ArquivoCertificadoTreinamento`** (1:1 com `Treinamento`, cascade): arquivo em tabela propria, nao em coluna de `Treinamento`, porque varias telas materializam a entidade inteira (perfil do trabalhador, motor de alertas, emissao de certificado) e arrastar bytes ali degradaria todas elas.

### Ajustes na trava de NR-06 da entrega de EPI

Motivados pela pergunta do usuario "o campo de EPI vai identificar que o funcionario tem NR-06?" — a resposta e sim, mas a trava existente (de `1a9767b`, PR anterior) tinha 3 problemas que o lancamento retroativo exporia:

1. **Certificado sem numeracao deixa de travar.** Antes exigia nº da lista de presenca (= nº do certificado); certificado externo antigo raramente tem numero. Agora exige so a data do treinamento.
2. **NR-06 vencida passa a bloquear.** Antes a trava so checava se existia o treinamento, nao se estava dentro da validade. Agora bloqueia vencido e avisa (nao bloqueia) quando vence em ate 30 dias.
3. **`CursoTreinamento.AtendeNr6`** (marcador explicito, boolean) substitui a heuristica de adivinhar pelo texto de `NormaReferencia` — bastava alguem digitar "NR-06 e NR-18" para o curso deixar de ser reconhecido e travar a obra inteira. A migration marcou sozinha os cursos cuja norma ja resolvia para "6"; a funcao `ehCursoNr6` no frontend mantem a heuristica antiga como rede de seguranca para curso legado.

Arquivo alterado: `src/AAHBRANT.SST.TeamsApp/src/pages/epi/EntregasTab.tsx` (fluxo de carrinho, ja refatorado por outro PR — ver licao abaixo).

### Licao para proximas sessoes: sempre `git fetch` antes de commitar

O primeiro commit desta feature (`0569b59`) foi feito sobre um master local 66 commits desatualizado. Isso quase causou um problema serio: nesse intervalo, outro PR ja mergeado tinha **refatorado `EntregasTab.tsx`** de um fluxo de "uma entrega por vez" para um carrinho (`confirmarCarrinho()`, `dadosComuns`, `sincronizarDadosTrabalhador`) e **ja tinha adicionado a propria trava de NR-06** (commit `1a9767b`) sobre essa estrutura nova. Alem disso, `CursoTreinamento` ja tinha ganhado `EhIntegracaoSeguranca` (modulo Terceirizado) e o seeder ja tinha versoes 5.12.0-5.14.3.

Se o PR `0569b59` tivesse sido mergeado direto, ele reverteria a refatoracao do carrinho de EPI e duplicaria a trava de NR-06.

Foi detectado a tempo com `git fetch origin && git status -sb` (mostrou `ahead 3, behind 66`) antes de rodar `gh pr create`. O trabalho foi refeito via `git cherry-pick` sobre `origin/master` num worktree separado, com 13 conflitos resolvidos manualmente (a versao do usuario descartada em `EntregasTab.tsx`, as 3 mudancas de NR-06 reaplicadas na estrutura de carrinho nova). So depois disso o PR foi aberto e mergeado.

**Regra para toda sessao futura**: antes de qualquer commit na pasta principal, rodar `git fetch origin && git status -sb` e conferir `behind`. Se `behind > 0`, nao commitar direto — atualizar primeiro (`git reset --hard origin/master` se a pasta estiver limpa, ou isolar o trabalho pendente numa branch antes).

### Medir impacto da trava de NR-06 vencida antes de qualquer decisao de producao

Na base de dados de teste (seeder de 200 trabalhadores), **89 de 200 estavam com NR-06 vencida**. Se a obra real tiver proporcao parecida, a trava (ja ativa em homologacao desde este deploy) vai bloquear a maior parte das entregas de EPI ate o mutirao de recadastro.

Acao sugerida: usar o filtro "Vencidos" da propria sub-aba Certificados em homologacao para medir o numero real antes de decidir quando levar essa trava para producao.

### Confirmar com SST/juridico a validade do lancamento retroativo

Registro retroativo com certificado anexado documenta a evidencia e a validade dentro do sistema, mas nao substitui o treinamento em si perante a NR-01/fiscalizacao. Cursos vencidos ou com certificado fragil podem precisar ser refeitos — vale confirmacao formal com a consultoria de SST da empresa.
